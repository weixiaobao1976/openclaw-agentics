# 📝 doc-filler - 文档智能填充技能

## 适用场景

- 将一份合同/协议中的信息提取，填入另一份空白合同模板的对应位置
- 将产品信息表中的数据填入报表模板
- 将 PDF/图片/网页上拷贝的文字内容整理填入 Word 表格
- 批量生成个性化文档（基于同一模板+不同数据）
- 阅读旧版本文档中的数据，填入新版空白表单

## 工作流程（5 步）

```
源文档/文字 ──①提取──→ 结构化字段 ──②扫描─→ 模板占位符清单
                           │                      │
                           └──③智能匹配────────────┘
                                    │
                              ④填充文档 → ⑤验证 → 发送给用户
```

### 步骤 ①：理解源文档

用户可能投喂：

- 一个 Word 文件路径（.docx）
- 一段文字内容（合同文本、表格描述等）
- 一个 PDF 文件（需先转为文字）
- 一个图片（需先 OCR 提取文字）
- **AI 直接用自己的能力阅读理解**，提取出关键信息字段

**核心原则：** 用 **你自己的理解能力** 解析源文档结构，而不是依赖工具。读懂了才能填对。

### 步骤 ②：扫描模板占位符

运行扫描脚本来找出模板文档中的所有待填占位符：

```bash
python {scripts}/doc_utils.py scan <模板文件路径.docx>
```

输出示例：
```json
{
  "paragraphs": [
    {"key": "甲方名称", "match": "{{甲方名称}}", "paragraph_index": 3, "sample": "...合同由【{{甲方名称}}】与..."},
    {"key": "身份证号", "match": "__身份证号__", "paragraph_index": 4, "sample": "...身份证号:__身份证号__..."}
  ],
  "tables": [
    {"key": "项目名称", "match": "《项目名称》", "table_index": 0, "row": 1, "col": 0, "header": "项目"},
    {"key": "金额", "match": "{{金额}}", "table_index": 0, "row": 1, "col": 2, "header": "金额(元)"}
  ]
}
```

支持的占位符格式（自动识别）：
- `{{字段名}}`
- `[字段名]`
- `__字段名__`
- `＜字段名＞`
- `《字段名》`
- 也检测空表格单元格（有表头但无内容）

### 步骤 ③：智能匹配

将步骤①提取的信息与步骤②的占位符进行匹配。

**匹配策略（按优先级）：**
1. **精确名称匹配** — 字段名和占位符名完全相同
2. **语义相似匹配** — 字段含义相近（如"甲方"→"甲方名称"）
3. **关键词匹配** — 从源文档中搜索占位符关键词附近的文本
4. **用户确认** — 有歧义时列出候选，请用户选择

也可以运行辅助脚本辅助匹配：

```bash
# 先将源文档内容保存为文本
python {scripts}/doc_utils.py match <源文本文件> <模板文件.docx>
```

### 步骤 ④：填充文档

将映射好的字段填入模板，生成新的 Word 文件：

```bash
python {scripts}/doc_utils.py fill <模板文件.docx> <输出文件.docx> <映射.json>
```

映射文件格式：
```json
{
  "甲方名称": "张三科技有限公司",
  "身份证号": "110101199001011234",
  "项目名称": "AI 智能文档系统开发",
  "金额": "¥500,000.00"
}
```

**填充原则：**
- 保持原文格式（字体、字号、颜色、对齐）
- 填充内容不破坏表格结构
- 填充后加下划线标记（方便人工复查）
- 数字/金额保持原格式风格

### 步骤 ⑤：验证完整性

```bash
python {scripts}/doc_utils.py verify <输出文件.docx>
```

预期输出：
```json
{"status": "complete", "message": "所有占位符已填充"}
```

如果有遗漏会列出：

```json
{"status": "incomplete", "unfilled": [{"key": "联系电话", "location": "段落 7", "match": "{{联系电话}}"}]}
```

**永远不要发送没有完全验证的文档给用户。** 如有遗漏，先尝试补填，补不了再问用户。

### 步骤 ⑥：发送文件给用户

- 使用 `message` 工具的 `attachments` 参数发送 .docx 文件
- 附上简短的填写说明（哪些字段填了什么、哪些可能需要用户手动确认）

## 示例对话流程

### 示例 1：合同信息迁移

**用户：** "这里有一份旧合同（合同2023.docx），帮我把它里面的信息填到新合同模板（合同模板.docx）里"

**我的操作流：**

1. **读源文档** → `python {scripts}/doc_utils.py read 合同2023.docx` 或直接用 AI 理解
2. **扫描模板** → `python {scripts}/doc_utils.py scan 合同模板.docx`
3. **匹配字段** → 自动匹配（AI 理解优先，脚本辅助）
4. **生成映射** → 构建 field_map
5. **填充文档** → `python {scripts}/doc_utils.py fill 合同模板.docx 已完成合同.docx map.json`
6. **验证** → `python {scripts}/doc_utils.py verify 已完成合同.docx`
7. **发送** → 通过 message 工具带附件发送，附上填充说明

### 示例 2：文字内容填表

**用户：** 发一段包含公司信息、项目信息、金额的文字  
"帮我填到这个报表模板（报表模板.docx）里"

流程同上，只是步骤①直接从对话中提取信息。

## 模板预处理建议（告诉用户）

为了让填充效果更好，建议用户在模板中：

1. **用明确的占位符标记空格** — 如 `{{甲方签名}}`、`[日期]`
2. **表格的表头保留好** — 智能匹配会根据表头推测内容
3. **保持格式一致性** — 同一类占位符用同一种标记法

## 限制说明

- 当前仅支持 `.docx` 格式（Word 2007+），不支持 `.doc`
- 复杂的嵌套表格（合并单元格）可能需要手动调整
- 图片中的文字无法自动提取（建议用 OCR 辅助）
- 填充后的下划线标记可以通过 Word 的"取消下划线"一键清除

## 脚本路径

```
{scripts}/doc_utils.py
```

所有文档操作都通过此脚本进行。
